          How it works

          From table to map

          1. 1

            PostgreSQL + PostGIS

            The facilities table stores each place as a geometry(Point, 4326), with park outlines as polygons. CHECK constraints reject bad values even if the API is skipped.

          2. 2

            Express API

            Node.js and Express run parameterised SQL and return GeoJSON. Reads are public. Adding, editing and deleting need an editor sign-in.

          3. 3

            Leaflet website

            The page fetches the API, draws the markers and outlines, and sends the form back to the API. Refresh the page and your change is still there, because it lives in the database.

          API endpoints

          GET/api/facilities
          All facilities as GeoJSON. Filters: category, sector, status, q
          GET/api/facilities/:id
          One facility
          GET/api/nearby
          Facilities within a radius, nearest first (ST_DWithin)
          GET/api/boundaries
          Park outlines as polygons
          GET/api/stats
          Counts by category and sector
          POST/api/facilities
          Add a facility (editor)
          PUT/api/facilities/:id
          Update a facility (editor)
          DELETE/api/facilities/:id
          Delete a facility (editor)

          About the data
          The 28 starting records were taken from OpenStreetMap (© OpenStreetMap contributors, ODbL) and are labelled with that source. Condition starts as "Not assessed" and entry as "Unknown" until an editor records a visit. Records added on this site are labelled "Field observation" or "User submitted", so they are never mixed up with the imported data.
